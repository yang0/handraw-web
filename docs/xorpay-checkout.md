# XorPay 结账修复（#254）

原流程先 POST `/api/pay/{aid}`，拿到支付宝付款二维码后却把用户跳转至 `/api/cashier/{aid}`。后者是另一个微信 JSAPI 收银台创建流程，重复使用同一订单编号和不匹配的支付类型会返回 `order_exist`。同时原实现只从 `info` 读取平台订单号，而官方支付宝响应的 `aoid` 位于顶层。

现在下单只调用一次 `/api/pay`，禁止对创建请求自动重试；付款入口指向本站 `/checkout/?orderId=…`，从已创建订单读取付款二维码和链接。刷新此页面、钱包的“继续付款”和15分钟内重复点击相同档位均复用现有待付款订单。平台订单号优先读取顶层，兼容旧嵌套格式。

结账详情接口只返回当前用户的订单，不返回商户密钥或支付签名。支付页定期查询订单，不创建订单；到账仅由校验过的回调或服务端查询结算，保持资金用途分离和回调幂等。创建结果未知时保留待核对状态，不标成确定失败；`order_exist`/`order_payed` 查询现有订单而非再创建。待付款页不代表款项已经到账。

隔离测试验证：重复点击一次创建、顶层订单号、付款页刷新不再调用创建接口、跨账号404、超时不重发、`order_exist`只查询、现金/积分独立到账和重复回调。CDP在桌面/平板/手机验证了本站付款页；模拟支付确认后只到账现金¥10，积分不变，无真实付款或退款。服务器部署备份及线上验证结果见 #254。

官方协议：[支付宝当面付](https://xorpay.com/doc/alipay.html)、[微信收银台](https://xorpay.com/doc/cashier.html)、[订单查询](https://xorpay.com/doc/query.html)、[二维码展示](https://xorpay.com/doc/qr.html)。
