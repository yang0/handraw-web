# Handraw Web 数据库

网站服务使用 PostgreSQL 16+ 保存账户、作品、讨论、图库、任务和账本。Redis 承担分布式限流、任务协调和缓存失效通知。数据库连接由 `backend/postgres_db.py` 管理，HTTP 请求结束后归还连接。

## 结构与升级

- `backend/postgres_v3_baseline.sql` 是新库基线，包含身份列、外键、唯一索引，以及 V3 作品与媒体完整性约束。
- `python -m ops.bootstrap_postgres_v3 --apply` 在空库事务中安装基线和后续迁移，并插入默认首页场景。连接配置见 [本地运维手册](local-operations.md)。
- 已有库使用追加的 PostgreSQL SQL 迁移。110 为已发布作品的 `ratio` 建立部分索引，115 为作者作品列表建立部分索引，构建时会锁住作品表写入。111 安装支付订单和 webhook 事件表；113、114、116 分别补齐论坛回复通知、增长事件与钱包收入通知。117 只更名唯一索引，保留索引对象和键。按 [运维命令](local-operations.md#34-初始化空库与升级现有库) 在事务中执行。启动时只检查所需结构和迁移版本。代码回滚保留已提交的迁移。

## 首页场景查询

公开场景列表按配置排序，一次读取全部有效置顶，再为有空位的场景查找候选。候选查询只返回卡片和排序所需列。按日轮换、互动权重和跨场景去重在服务端执行。110 的部分索引适用于按比例筛选已发布作品的查询。

## 首页场景缓存

Redis 共享响应与进程内短缓存最长保留 120 秒。缓存键包含数据库、日期、样本上限、演示模式和 Redis 修订号。配置和置顶变更提交后递增 Redis 修订号，其他进程随之淘汰旧响应。Redis 不可达时直接计算结果。缓存命中时按主键批量校验当前作品可见性、封面、标题和作者。

HTTP 响应使用 ETag 和 `Cache-Control: public, no-cache`。浏览器与共享缓存每次向服务端校验，内容未变时收到 304。

## 作品查询与热门翻页

最新作品以时间和唯一 ID 稳定排序，使用游标继续读取。热门列表将首次排序的作品 ID 存入 Redis，后续请求可交给另一服务进程；每页仍查询数据库，排除已隐藏或删除的作品。会话按数据库、用户、筛选与演示模式隔离，保留 30 分钟，每库最多 128 个。Redis 故障时使用按数据库隔离的有界本地会话。

关联资源使用 PostgreSQL 原生 JSON 数组成员和展开操作，筛选按完整编号匹配。写入显式使用 `RETURNING` 与 `ON CONFLICT`，连接层仅转换参数，不探测自增列或改写 SQL 方言。
