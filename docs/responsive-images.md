# 全站响应式图片与缓存（#253）

图片的原始地址属于业务数据；显示地址由组件按当前容器和屏幕像素密度选择。画风、图型、作品/论坛、个人中心、文章、画布、系列图、消息与弹窗、审核后台和公开画廊共用这一规则，下载、发布、引用、导出和原图检查使用原始地址。

## 前端接口

`demo/assets/image-loader.js` 是实现来源，`plugin/public/image-loader.js` 是同一组件的发布副本，测试检查两者逐字一致。所有入口加载组件；模板使用 `data-hw-src` 避免先下载原图，旧的原生 `img` 也会被自动接入。动态更新使用：

```js
HandrawImages.set(imageElement, originalUrl);
HandrawImages.original(imageElement); // 下载、引用、业务保存使用这个地址
HandrawImages.url(originalUrl, 640); // 仅供非 DOM 预览探测指定目标像素宽度
HandrawImages.scan(container);      // 通常由增量观察器自动完成
HandrawImages.prepareHtml(html);    // 富文本显示前改成惰性图片地址
HandrawImages.originalHtml(html);   // 富文本保存/发布前恢复原图地址
```

组件根据显示宽高、contain/cover、DPR（最高3）选择向上取整的像素档位：48、96、160、240、320、480、640、960、1280、1600、1920、2560。容器扩大、窗口/DPR改变时升级清晰版本，缩小时复用已经解码的较大图，避免重复下载。新列表中的较小图片独立选取较小版本。请求有并发上限、可见性调度、失败重试；source 改变后旧响应不会替换新图。

svg、内联 data/blob、本地裁剪/尺寸验证和动画保留其类型与语义；不把动画转成静止首帧。不可控第三方源（包括供应商二维码）通过相同组件调度，但不擅自添加缩略图参数或建立任意网址代理。第一方图片镜像可映射到应用的媒体接口。公开画廊构建设置 `HandrawImageConfig.mediaOrigin`，使尺寸请求到达实际提供变体的后端，而非被静态 CDN 忽略。

## 后端与权限

`backend/image_variants.py` 为 `/images/`、`/uploads/`、`/generated/`、`/avatars/` 及公开 assets 位图生成 WebP。等比、不裁剪、不放大；保留透明度，校正 EXIF 方向并保留 ICC。原图内容不改写。

- 缓存键包含规范路径、文件修改/变更时间、大小、目标档位和编码版本，使用稳定 SHA256，跨进程/重启复用。
- 线程分段锁和操作系统进程锁避免同一变体重复编码；独立临时文件原子替换，崩溃不会留下半张图。每进程最多两个编码任务并发。
- 缓存位于私有存储的 `thumbs` 或 `HANDRAW_THUMB_CACHE_DIR`。默认512MB、30天回收；`HANDRAW_IMAGE_CACHE_MAX_BYTES` 可调整容量。清理仅匹配组件生成的缓存文件名，不操作普通原图文件。
- 公开尺寸变体通过 ETag 重新验证，未变化返回304；源图改变生成新缓存和新 ETag。私人变体每次先鉴权、先确认原图存在，再读取缓存，保持 `private, no-store`。缓存文件不能直接通过网页地址访问。
- 新版尺寸地址包含 `iv=webp-v2`，避免 CDN 复用历史缩略图实现的长缓存。所有应用 HTML 中的本地 JS/CSS 使用实际内容哈希作为版本，preload 与脚本地址一致；文件更新自动变更地址，避免人工版本号重复导致加载旧代码。
- 解码失败、SVG/动画或缓存不可写时安全回退，不影响原图下载；没有引入任意远程图片下载代理。

## 验收证据

真实 CDP 9221 在1440/820/390宽度及DPR2检查了画风、图型、作品、文章和后台；生成结果使用模拟网关，无真实模型费用。实测36px头像请求48px、263px卡片请求320px、手机155px卡片请求160px；DPR2的370px卡片请求960px。检查了弹窗/动态更新和原图地址保存。

自动化覆盖尺寸/压缩、EXIF、透明度、不放大、动画、源图更新失效、跨进程一次编码、原子写、容量清理、公开304、私有图跨用户/删除后访问、容器扩大、同址失败重试、原地址不变、全站模板/入口接入与前后端尺寸契约。构建后的旧画廊使用同一组件。最终用例和部署结果记录于 #253。
