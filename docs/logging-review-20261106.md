# 日志系统评估（2026-11-06）

本次问题是 Google 用户登录后 `/api/boot` 初始化审核权限时执行了 SQLite 专属 SQL，当前 PostgreSQL 运行环境拒绝执行。原代码把异常转换为 HTTP 500，却没有记录；`BaseHTTPRequestHandler.log_message` 也被置空，因此两个标准输出重定向文件里都没有故障证据。

## 已落实

| 缺口 | 本次处理 |
| --- | --- |
| 四种业务请求重复捕获异常，但未记录 | GET、POST、PUT、DELETE 及 OPTIONS 使用统一入口；业务错误保留原状态与错误码，未知异常返回通用 500 |
| 主动返回 502/503 可能绕过异常捕获 | 在 `send_response` 统一记录所有 5xx；有活动异常时附堆栈，没有异常时仍记录状态与请求元数据 |
| 请求建立、清理阶段的异常不经过业务入口 | 实际服务使用 `HandrawHTTPServer.handle_error`，将连接层异常写入应用日志 |
| 无法关联浏览器与服务端错误 | 服务端生成请求编号，写入日志、`X-Request-ID` 和错误 JSON 的 `requestId`；不信任客户端提供的编号 |
| 缺少时间、等级、请求耗时 | 统一日志格式；API 摘要含方法、去查询参数的路径、状态和发送响应头前的耗时 |
| 重启覆盖日志、文件无上限 | 新增按端口划分的追加日志，10 MiB 轮转、保留五份备份；兼容旧 stderr 日志 |
| 恢复任务静默忽略异常或线程退出 | 生图检查的任务级失败记录警告；轮次级失败记录堆栈并继续下一轮；回填启动失败也记录 |
| 日志可能含 OAuth 参数或凭据 | 不记录请求头、请求体和查询参数；格式化器对 URL 查询、连接串凭据及常见密钥字段作二次脱敏；移除文档导入成功日志中的原始文件名和文章标题 |
| PostgreSQL 登录初始化失败 | 按 SQL 方言检查可选冷启动表；作者名称比较改用跨数据库的 `LOWER`，保留种子贡献排除逻辑 |

正常 API 请求以 INFO 记录，4xx 为 WARNING，5xx 为 ERROR。健康检查和成功的静态资源不逐条记录。`duration_ms` 是发送响应头前的处理时间，不包含客户端接收响应体的时间。

## 后续优先级

1. **故障可见性**：前端错误面板直接显示并支持复制请求编号。目前编号已存在于响应头和错误 JSON，但当前启动失败 UI 只展示 HTTP 状态。
2. **就绪检查**：将进程存活与依赖就绪拆开，给 PostgreSQL、Redis、必要 schema 增加有超时的真实检查。现有 `/api/health` 固定返回 `db: true`，不能据此判断业务正常。
3. **告警与频率控制**：给连续 5xx、OAuth 上游失败、队列积压和恢复线程连续失败设置阈值。总闸能记录异常，无法自动发现被业务代码捕获后仍返回 200 的错误；这些路径需要业务事件和指标。
4. **后台任务关联**：文档导入已有任务失败堆栈，但其他模块仍有用于降级、清理、可选能力的静默 `except`。应逐处区分可忽略事件与真实失败，为任务统一 `job_id`/`generation_id`，避免批量将全部降级行为升级为 ERROR。
5. **生产日志收集**：多进程或多实例运行时使用 journald/外部日志收集器做轮转、检索和告警；当前 Python 文件轮转适合单进程。旧 `.out.log/.err.log` 在一次运行内仍无大小上限；不能只依赖这些文件保存历史。
6. **脱敏复核**：当前规则不是通用秘密识别器。历史异常字符串、上传路径及第三方异常仍可能含业务资料；后续应限制字段并采用结构化事件，避免拼接任意上游响应或用户内容。

总闸应只负责记录、返回可追踪错误及隔离一次请求的失败，不能把不确定的生图状态自动改成成功、退款或重新提交。后台恢复继续保留原有计费和重试规则。

## OAuth 303 失败补充检查

后续真实 Google 登录以 `oauth_state_invalid` 返回登录页。日志显示授权发起与回调间隔约 9 秒，检查时对应 Google 授权记录仍未过期。现有日志没有记录被业务层转换为 303 的拒绝原因，因此不能单凭该次记录断定究竟是 Cookie 缺失还是不匹配。

隔离 HTTP + CookieJar 回归复现了地址切换问题：从 `127.0.0.1` 设置的浏览器 Cookie 不会随 `localhost` 回调发送。控制台同时允许两个回调地址不会改变 Cookie 的 Host 绑定。本次在创建授权状态前将登录入口切换到配置回调的 Host，并把本地菜单链接统一到 `localhost`；账号绑定在 Host 不同时拒绝继续，以免切换到另一个 Host 的不同账号。

授权回调拒绝现在额外记录 `event=oauth_callback_rejected`、provider、错误码、请求编号和枚举原因。覆盖 Cookie 缺失/不匹配、状态过期/已消费、提供方不符及 PKCE verifier 缺失，仍不记录授权参数或 Cookie 值。普通 HTTP 303 摘要不再是这类失败的唯一证据。

33 项相关回归通过，其中新增真实 HTTP/CookieJar 回归覆盖 Google 登录跨地址往返、Google/GitHub 登录入口、跨 Host 绑定拒绝、重复回调以及各状态拒绝原因。提供方身份接口均为模拟，不代表已替用户完成真实 Google 授权。输出为 `.local/oauth-origin-final-20261106.log`。
