# Studio 2.0 · #136 · AI 套图规划与创作工作台交互收敛

日期：2026-11-10。开发分支：`studio2-issue136-plan-and-ux-20261110`。**仅工作流/创作台体验改造，严禁合入 main；PR #131 必须保持 Draft；Issue #132 生产仍 NO-GO。**

## 用户五项反馈与交付界限

1. **“AI 规划失败：结构不符”**：`backend/studio_ai_plan.py` 现将严格的 schema/可用资源/槽位张数/画幅/文章锚点等完整验证封装复用。对于 **series** 模型第一次返回 JSON 不合法、缺字段、张数不符、无效的授权资源编号等可恢复错误，限额 **一次**低温度重试，要求仍从**当前用户已授权的完整画风/图型目录**选取、恰好 count 条槽位；只将公开资源用途说明截短，不删资源，也没有任何 few-shot 预置画风偏置。模型持续不符合结构就仍返回明确错误，并在系列编辑器中显示具体结构问题和代码；不写入无效草稿，不调用生图或扣取生图费用。**未授权的资源 403 不重试、不回填；CAS 与锁定字段继续受保护。** 独立测试使用 Mock gateway，无真实上游凭据，不能宣称所有第三方模型 100% 成功。
2. **取消“项目中心”**：顶层导航不再显示 Project Center，也不提供可进入的项目列表页。旧 `?view=projects` 收藏地址跳转至图片表单 `?entry=quick`；`?project=ID` 仍直接恢复指定用户有权访问的云端项目，保留恢复、跨标签冲突、账号隔离以及作品/工作流历史。**未删除数据库项目表、用户草稿或存储记录**。原项目中心模块保留作为历史兼容内核，但用户不再需要经过这个页面。
3. **表单 ↔ 画布**：主导航中原有“简洁编辑”和“画布编辑”两个按钮合并成唯一 `#studio-mode-view-toggle`，在表单时显示“切换到画布 →”，在画布时显示“← 返回表单”。仍使用原来的 `switchCreationStage` Graph/Spec 投影及 CAS 规则；切换不得创建空项目、误发生成请求或覆盖人工已选画风/图型/文章内容。复杂 Graph 继续安全的部分表单投影，不把无法映射的高级节点静默删除。
4. **图片创作的画风模式位置**：`单画风/双画风融合` 放入同一 `make-image-resource-group` 选择区域，紧邻画风、图型、主题色卡片。融合时动态展开角色画风与场景画风，切换模式保持原来状态机；在手机窄屏使用两列/单列避免溢出。
5. **画布按钮减法**：画布顶部只保留唯一醒目的“运行画布/运行选中分支”、属性查看、折叠“更多工具”；AI GraphPatch、便签、分组归入低频菜单。删除这里与导航或底部工具条重复的保存/返回表单/撤销/重做；“运行此分支”重复入口也删除，但选中输出节点时顶部主按钮仍执行该分支。历史、撤销、右下角保存/同步、缩放与项目执行能力均保持，不更改画布的性能敏感底层布局/渲染路径。
