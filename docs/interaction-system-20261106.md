# Handraw 全站可观测交互设计规范（2026-11-06）

## 设计主张

**让等待变成看得见的创作。** 保留暖纸、墨字、朱红强调色，优先使用轻量、明确、可恢复的状态可视化，而不是眩目却不可信的动画。

交互的三层反馈：
1. **即时反馈（<300ms）**：按钮状态、轻触压感、禁重复提交。
2. **过程反馈（>2s）**：非阻塞任务卡、阶段名、已等待时长、失败重试和可解释的取消行为。
3. **结果反馈**：完成摘要、实物预览、保存来源与回退方式。

**真实性原则**：仅在后端确实提供计数时显示百分比；不知道进度时用不确定进度条、阶段、运行时间。没有后端取消接口时只允许“收起进度”，不写“取消任务”。

## 当前落地（main）

- `demo/assets/task-journey.js`：异步文档导入任务卡；分段计数；阶段时间线；最小化任务胶囊；浏览器刷新后根据不敏感的任务 ID 恢复查询；完成后的 Markdown 下载退路。
- `demo/assets/task-journey.css`：纸张浮层、朱红进度、轻量呼吸动效、手机布局、`prefers-reduced-motion`。
- `demo/assets/studio-app.js`：两个文章导入入口改用 `POST /api/studio/imports` 与 `GET /api/studio/imports/:id`；ZIP 导出增加可见处理状态。
- `demo/assets/studio-batch.js`：AI 批量规划增加可见耗时状态。
- `backend/server.py`：从实际持久化的任务状态推导 `queued/extracting/structuring/validating/completed/failed`，并返回真实已处理分段数量。
- 不额外向 LocalStorage 保存文章正文、文件字节或任何凭据；任务恢复仅保存任务 ID、文件名、开始时间。

## 验收标准

1. 文档上传后在任意明显等待阶段都能看见具体任务状态，超过 10 秒不得退化为无反馈。
2. 长文章处理可观察分段进度，百分比不超过服务端实际 `done/total`；提取和校验阶段不得伪造百分比。
3. 导入失败或断网后保留编辑器原稿，不重复消耗额度；刷新可恢复查看已提交任务。
4. 文章标题不因导入 Markdown 的 H1 被重复展示。
5. UI 显示进度与服务器状态一致；测试覆盖队列、处理中、成功、失败及浏览器无障碍语义。
6. 交互不泄露文章正文、身份凭据或 OAuth 回调参数到浏览器持久化存储或日志。
7. 桌面、移动端及减少动态效果偏好下均可操作。

## 现阶段边界

文档导入为异步进度可视化的第一版。后台队列仍以内存暂存上传文件，进程重启时任务可能失败；不能宣称实现了完整的跨进程断点续跑。若任务在刷新后完成，面板支持下载结果，但再次回填到特定编辑器仍待进一步实现。

同步模型规划和 ZIP 导出目前只有**真实已等待时间**与活动状态，不是可恢复的后台任务，也没有真实百分比。
