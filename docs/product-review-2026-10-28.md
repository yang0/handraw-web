# Handraw 本地产品评审 · 2026-10-28

评审对象：当前本地运行的主站 3080、创作台 3081、论坛 3082、后台 3083。依据实际页面、首页与创作台截图、项目产品约束和相关源码。当前页面明确处于演示环境；本报告不代表生产环境验收。

## 产品判断

产品已有丰富的视觉资源、在线创作和社区复用入口。当前最值得投入的是帮助新用户完成第一张满意的图：看见合适的效果 → 选择或复用 → 输入主题 → 明白费用 → 生成并保存 → 自愿分享。

暖纸、墨色字体与朱砂操作色有辨识度。资源卡有真实可见的图像，“去创作”和论坛复刻链接把发现与使用连接起来。使用指南已存在，说明生成、保存与主动分享的边界；这些能力应继续作为主线。

首轮观察到的主要问题是信息优先级：贡献奖励、曝光权重、节点结构、页面实现方式先于用户眼前要完成的事情。建议先提高首次成功率，再扩展榜单、商业激励和复杂工作流。

## 已核验的边界与待决策事项

- 使用指南已经说明“未主动发布的文章与图片只属于你”，并有四步入门流程。问题是引导与创作入口的结合程度，不能继续把指南列为缺失。
- 游客访问后台看到的是角色介绍与登录页。本轮未点击角色切换，也未进行写入或权限攻击测试，不将演示按钮认定为生产越权漏洞。
- 现金充值在源码中受演示开关限制（`backend/runtime_policy.py:43–47`）。真实支付、免费额度、付费资源权益和旧站迁移仍需产品规则与专项验收，不能凭接口存在视为可运营。
- 本轮未生成付费图片、未发布社区内容、未操作后台数据、未部署生产环境。

## 建议的迭代顺序

1. 收口首屏用户文案；完成本轮评审和 DeepSeek 协作入口验证。
2. 单独调整资源目录与首页信息层级，核验桌面和手机浏览、筛选、去创作。
3. 设计创作台入门流程和费用可见性，核验首次生成、失败恢复与草稿连续性。
4. 在非演示配置下完成真实内容、账号、额度、隐私与权限验收，再决定开放范围。

建议记录目录到创作台的转化、首次有效生成完成率、生成耗时与失败恢复率、保存与主动分享率。本轮没有采集这些指标的可靠基线，不填入虚构比例或增长目标。
