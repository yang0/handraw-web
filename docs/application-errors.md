# 应用错误与系统异常

用户可见的失败应保留操作出口和问题编号；服务端日志保留定位信息。API 的 JSON 响应、浏览器导航错误页、前端提示与系统异常分别处理，共用请求编号进行关联。

## 后端入口与响应

- GET、POST、PUT、DELETE、OPTIONS 经统一请求异常入口。业务错误保留状态和错误码；未知异常返回通用 500。
- 浏览器导航（`Sec-Fetch-Mode: navigate`，或接受 HTML 且没有明确要求 JSON）发生错误时，返回 Handraw 错误页，包含“返回首页”“前往登录”和问题编号。页面直接由服务端渲染，不依赖应用脚本。
- 普通 API 调用继续返回 JSON；错误包含 `requestId`，响应头包含相同的 `X-Request-ID`。旧 `send_error` 路径也进入统一错误响应；HEAD 不发送响应体。
- 5xx 在响应出口记录状态、耗时和活动异常堆栈。连接建立/清理阶段有 HTTP server 兜底；主线程和后台线程的未捕获异常分别记录 `process_unhandled_exception`、`thread_unhandled_exception`。记录不代表进程或线程自动恢复。
- 原始异常、SQL、内部文件路径不展示给用户。HTML 中的业务提示转义输出，设置不缓存及限制资源加载的 CSP。

## 前端入口

`demo/assets/error-boundary.js` 在主站、创作台、社区、后台的应用脚本之前加载，没有应用依赖。

| 场景 | 行为 |
| --- | --- |
| 未捕获脚本异常、未处理 Promise 异常 | 显示可关闭、可刷新的提示，并尝试上报位置和问题编号 |
| 关键脚本加载失败 | 显示恢复提示；普通图片加载失败交由图片组件处理 |
| 公共 API 客户端遇到 5xx、网络错误、无效 JSON | 构造统一错误，保留 HTTP 状态、错误码和服务端请求编号；交给调用位置显示，未处理时进入全局提示 |
| 正常业务 4xx | 保留业务说明；已有表单/组件可以显示具体提示，不作为崩溃自动上报 |
| 主站初始化失败 | 显示重试入口和问题编号；保留原错误对象，防止一次失败重复上报 |
| 公共 UI 订阅回调抛异常 | 记录并显示错误提示，不再只打印到 console |

主站公共 `apiJson` 和后台 `api` 使用统一 `fetchJson`。应用模块应使用公共 API 客户端；自行直接调用 `fetch` 并捕获错误的代码仍需明确处理失败，不能依赖全局事件捕获已经被吞掉的错误。主动取消的请求保持 `AbortError`，不作为网络崩溃上报。

## 上报与查找

前端通过同源 `POST /api/client-errors` 上报白名单字段：错误类别、错误类型、频道、脚本文件名、行列、HTTP 状态、相关请求编号和客户端事件编号。**不上传原始错误消息、完整堆栈、完整 URL、查询参数、Cookie、请求头或请求体。**

接口限制为 4 KiB，校验来源和字段，每 IP 每分钟最多 20 次；本地无 Redis 时使用同一业务范围的内存限流。客户端同一错误对象去重，每分钟最多尝试 5 次，超量提示关联最近的上报事件。上报失败不会触发新的上报，网络不可用时仍保留本地恢复提示。

日志写入 `.local/logs/web-3080.log`，事件为 `event=client_error`。已知服务端 API 故障优先显示原请求编号；纯前端错误在上报成功后更新为接收接口的请求编号，原客户端编号同时保存在 `client_event_id`，两者都能检索。

```powershell
Select-String -Path .local\logs\web-3080.log* -SimpleMatch '<页面显示的问题编号>'
```

## 登录状态一致性

本地页面优先跟随 Google/GitHub 回调配置的本机 Host，未配置回调时使用 `HANDRAW_PUBLIC_URL` / `HANDRAW_BASE_URL`，将 `127.0.0.1` 与 `localhost` 的文档入口统一到同一 Host。仅处理同端口的两个本机别名，不改变生产子域名路由，也不转发 API 或 OAuth 回调参数。

已登录用户再次点击 Google/GitHub **登录**时，直接返回账号页面，不创建授权状态或隐式绑定第三方账号。**绑定**仍需显式入口、有效会话和原有浏览器校验；跨 Host 的绑定继续拒绝。已登录用户打开主站 `?view=auth` 时直接显示账号设置，避免重复呈现登录表单。

## 验证

- Python HTTP 回归：导航 HTML/API JSON 分流、转义和通用 500、原生 404/HEAD、上报白名单、体积、来源与限流、请求编号、系统线程异常、已登录 OAuth 入口和本地页面 Host。
- Node 执行真实前端边界代码：运行时异常、Promise、API 请求错误、无效 JSON、无内容响应、离线、脚本资源错误、去重、频率上限、隐私字段及已登录页面路由。
- 隔离 HTTP 服务的真实浏览器验收：500 错误页可见；触发脚本异常后恢复提示可见，页面编号与 `client_error` 日志一致。测试数据及截图仅保存于忽略目录 `.local/`。
