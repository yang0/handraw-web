# 改版交付与内容维护

依据用户提供的《HandRaw Style 改版完整方案 V1.0》实施。用户补充的“移除 ZIP 主流程、接入现有在线生图、限制图片请求”优先于附件原有假设。

## 页面结构

- 首页：产品定位与搜索、两个主要操作、真实画风图、按用途开始、八个精选画风、三个用途组合、三步教程、入门指南、真实社区作品。
- 主导航：探索 / 创作台 / 社区 / 指南；Logo 返回首页。个人创作在登录后的账户入口。
- 探索：官方画风、图型、配色，编号／旧编号／名称／关键词搜索；每批十二条，滚动到附近才加载图片。社区画风入口独立，保留作者来源。
- 创作台：类型、主题、画风／图型／配色；比例与情绪折叠。生成指令复用原拼装器；组合链接只包含公开枚举参数，不带用户主题或私人图片。
- 社区：作品、经验、画风与图型、讨论。原论坛、账号、帖子和作者主页链接继续可用。
- 指南：聚合已有公开教程帖的链接与简介，点击直接进入原帖，不单独维护详情正文。

## 初始内容

`plugin/content/catalog.json` 是官方公开资源的版本化快照；`editorial.json` 管理精选资源引用、编辑文案、用途组合和指南。首页示例图来自真实官方图库。用途组合明确标为“组合建议”，不冒充已经完成的案例或用户作品；不创建假作者、假互动或推广帖子。

在更新官方库后运行：

```powershell
python ops/refresh_content.py E:\handraw-style\skills\handdraw-style-prompter
python -m unittest discover -s tests -v
```

检查差异后提交并部署，计数由该快照生成，所有页面使用相同编号。此操作不修改公开 Skill 仓库。

## 在线生图

复用服务器已部署的 chatgpt2api 异步图片任务，服务端读取 `/home/yang0/handraw-data/image-service.json`，凭据不进入 Git、前端或 URL。

按现有试运行创作者权限开放；首版默认每天提交三次、同时一张，次数可通过 `handraw_generation_daily_limit` 调整。图像任务使用稳定 ID，提交和确认重试不会新增任务或重复占用次数。没有充值、付款或自动发布。

任务记录按用户独立保存；状态查询只查询本人任务，每十五秒一批。生成图片通过登录鉴权的服务器端地址访问，前端不暴露号池原始图片地址。用户点击“分享这张图”后仍需确认投稿表单与权利声明才发布。

首次绑定现有服务：

```bash
python3 ops/connect_image_service.py
```

此命令只在服务器运行，先验证已有服务的鉴权与模型接口，再把配置写入公开目录之外；已有配置先备份，不生成图片，不输出密钥。

## 静态分发

公共导航、探索、画廊、拼装器保留分层部署。`build_public.py` 在独立版本目录构建覆盖层，不改写静态仓库。图片队列保留两张并发、至少 600ms 的请求间隔；失败暂停，不遍历备用 URL。旧附件接口保留兼容，新投稿不制作 ZIP。
