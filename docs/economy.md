# 生图余额、社区积分与规格额度

人民币余额只支付生图；社区积分用于内容与资源权益，不兑换现金或生图余额。一次性基础额度默认为每账号10张1K，长期有效，不每日恢复。文章与系列AI规划免费，保留短时防滥用限流。

## 用户与运营规则

- 同模型、分辨率档位与质量，不论单图、系列、文章或画布，使用同一价格。预览、保存、编辑免费。
- 报价10分钟内有效，提交时预占免费额度与人民币；保存有效结果后按逻辑图片结算，明确失败或未开始取消释放。结果未知时查询原任务，不重复扣款、不立即退款。意外多返回图片不追加收费。
- 1K不能抵扣2K/4K。新规格记录实际像素、比例映射、模型、质量与价格版本。默认规格未标记验证、未填写售价；管理员必须核实网关后开放。未定价规格在免费额度用完后拒绝付费任务。
- 生图余额充值¥10/¥30/¥100；积分购买¥5/50分、¥10/100分、¥30/300分。不打折、不返分。人民币金额用整数分保存。
- 两类购买分行显示并保留预设；XorPay 支持各自输入 1–10000 元整数金额，积分按每元 10 分由服务端计算。自定义订单沿用金额核验、幂等到账及原路退款流程（#260）。
- 全员基础额度调整改变每账号生命周期授权总量；额外赠送按用户、用户组或全员形成独立批次。已用、预占扣除，降低额度不追扣已交付结果、不取消已受理任务。赠送可设置期限，默认永久；撤回只影响未预占部分。
- 公开浏览、作品、讨论、点赞收藏免费。资源一次解锁持续站内使用；完整付费定义不向买家返回。明确收费的提示词帖解锁后可查看复制。同一资源各入口共用授权，不重复收取讨论帖费用。
- 账号验证一次20分；签到1分、每月20次；优质作品5分、原创资源审核通过20分、优质教程10分，各类每月最多10件。同一内容只奖励一次。普通发布、点赞收藏、邀请注册与荣誉晋级不铸币。
- 社区资源/内容解锁：作者80%向下取整，7天后可用；其余回收，官方资源全额回收。打赏全额给作者，悬赏按托管额结算。积分来源追踪优先消费赚取/赠送，再消费购买部分。
- 有效内容退款恢复买家原积分来源并冲回作者分成；已结算的异常收入可以形成明确积分欠款，以后收入先补足。锁定积分钱包会暂停分成结算，人民币账户不因此停用。
- 未消费充值可申请原路退款，申请时冻结可核实的原订单剩余本金。目前自动原路退款适配XorPay；其他支付提供方需要核对其退款结果。退款POST不自动重试，未知结果保留冻结；管理员填写支付平台凭据和结果进行核对，不重新发送退款。
- 管理员关闭账号保留财务与积分来源记录，并撤销会话和令牌，不物理删除账务身份。

## 接口与账务

`GET /api/economy` 返回人民币可用/冻结、社区积分、按规格免费额度、作者收益和各自明细。`/?view=wallet` 专注资产余额、充值/买分与收支流水；购买订单拆分至独立订单记录页（`/?view=orders` 与 `/orders`），通过 `GET /api/billing/orders`（支持 `status`、`purpose`、`page`、`limit` 筛选与分页及订单可退本金/退款申请状态，响应带 `Cache-Control: no-store`）展示与操作（#263）。`POST /api/studio/quote` 接收 `items`，返回 `quoteId`、各项规格快照、免费数量、`totalCents`和过期时间。所有入口先报价确认，再携带 `quoteId` / `quoteIndex` 提交。画布使用 `maxAmountCents`，不再用 `maxCredits` 指代资金。

`GET/POST /api/admin/economy` 管理规格、全员额度预览/确认、赠送与撤回、积分价格档位，返回现金/积分流水及冻结额对账报告。优质作品/教程奖励使用 `/api/admin/economy/reward`。支付冲回形成欠款时，后续收入先抵欠，只有实际可用部分进入来源批次或未消费充值本金；已受理的冻结任务仍正常结算/释放。积分来源对账同时比较批次可用量与钱包非负可用余额。所有管理操作记录操作人及原因审计。人民币和积分流水禁止更新/删除，冲回通过关联追加流水完成。

`POST /api/billing/refund-requests` 申请退还未消费部分；`POST /api/admin/economy/refunds`审核执行或记录未知退款的明确核对结果。现金消费分配到充值订单本金批次；积分消费分配到来源批次。支付回调、任务结算和退款均使用幂等记录。

新增账务表由 `backend/postgres_119_economy.sql` 创建；`backend/postgres_120_contribution_guards.sql` 追加奖励内容指纹并更新风控暂停校验；`backend/postgres_121_reward_promotions.sql` 只替换已知旧默认奖励宣传，不覆盖管理员自定义公告。旧 `wallets/ledgers` 专用于积分，历史记录保留。旧生图计费字段仅供历史追溯，新的现金费用写 `amount_cents`、规格快照和独立预占记录。后台恢复使用数据库状态，缓存不能决定资金或权益。

## 上线前配置与迁移

1. 使用 `HANDRAW_ECONOMY_UPGRADE_URL` 显式指定目标，先运行 `python -m ops.upgrade_economy`进行只读检查。存在真实支付订单（含未完成订单）但尚未安装119时拒绝自动切换。
2. 确认未发布的内测库无真实支付，备份后设置 `HANDRAW_ALLOW_ECONOMY_UPGRADE=YES`，运行 `python -m ops.upgrade_economy --apply`，依次应用119、120和121。迁移新增且可重复执行，保留旧积分和授权，不将积分折成现金。
3. 旧代码与新代码不同时受理扣款；停止接单并排空旧任务后切换代码。人民币余额初始为零。清理客户端旧缓存版本，重新预览旧工作流费用。
4. 管理员验证实际网关的每个模型/规格及尺寸，配置成本和售价后开放。不要用测试价格作为生产定价。
5. 在支付测试模式核验现金充值、积分购买、重复回调及退款。核对财务报告和任务流水后才开放真实付款。

XorPay原路退款协议参考[官方退款文档](https://pay.xorpay.cn/doc/refund.html)。调用发生在事务外，异常不视为确认未退款。
