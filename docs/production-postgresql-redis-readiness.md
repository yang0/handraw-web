# Handraw PostgreSQL 与 Redis 运行边界

应用后端只使用 PostgreSQL 16+。连接、迁移、备份和验收命令见 [本地运维](local-operations.md)。当前代码改造与本地隔离验收不代表生产已部署。

## 数据与查询

- PostgreSQL 是账号、会话、作品、资源、媒体关系、积分账本、购买退款和审核的权威库。
- `backend/db.py` 导出 PostgreSQL 数据库类型。`HANDRAW_DATABASE_URL` 必须指定业务数据库；配置错误直接失败。
- 每个进程使用有界连接池；连接配置语句、锁等待和空闲事务超时。请求结束归还线程连接。
- 钱包、社交计数和导入准入依赖数据库事务与行锁/事务锁，跨进程保持一致。
- 作品列表使用索引、稳定排序和游标分页。公开投影读取规范化媒体关系，权限检查必须在服务端完成。
- 新库使用 `ops/bootstrap_postgres_v3.py`；已有库由数据库所有者执行缺失的追加迁移，应用启动只验证 schema。
- 数据库只向前迁移，代码回退不回滚迁移。禁止用生产数据库执行测试。

## 缓存

- Redis 用于共享限流、首页场景响应与修订通知、热门作品分页排序会话。
- 键按环境、数据库及必要的用户/筛选条件隔离，设置 TTL 和容量上限；连接池复用。
- 热门分页的排序会话可跨进程读取，每页仍重新检查作品可见性；Redis 故障时使用按数据库隔离的有界本地会话。
- 首页缓存失效不能只通知当前进程。无法验证共享修订时直接查询数据库。
- 余额、永久授权、账本与审核结果不以缓存作为权威来源。
- 私有上传与生成文件通过授权接口访问；不能统一配置为公开 CDN 缓存。

## 部署与验证

- Discourse 插件与独立 Python 后端是不同服务，数据库和身份映射边界必须明确。
- 所有数据库集成测试创建 UUID 命名的临时数据库，结束后销毁；CI 使用 PostgreSQL 与 Redis 服务。
- PostgreSQL 备份使用一致性快照和原生工具，媒体单独备份，恢复在隔离数据库中演练。
- 生产发布前备份现有变更，使用精确提交；服务器只允许快进拉取。密钥放受限环境/文件，不进入 Git。
- 持续监控连接池饱和、慢查询、锁等待、请求错误率与延迟，缓存命中/故障、Redis 内存和任务积压。
- 生产凭据、容量指标、异机恢复与实际发布验收必须在真实环境单独完成，本地测试不能代替这些结论。
