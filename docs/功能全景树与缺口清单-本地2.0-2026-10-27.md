# Handraw 本地 2.0：功能全景树与缺口清单

核对日期：2026-10-27。对象：本地新版主站 `3080`、创作台 `3081`、论坛 `3082`、管理后台 `3083`。

本文把网站应具备的功能按用户使用路径展开，标明当前实现、缺口与问题，可作为后续开发和验收清单。依据本轮源码核对、前一轮本地浏览与隔离数据库复现；不代表线上旧站的状态。

## 阅读方式

| 标记 | 含义 |
| --- | --- |
| `[已有]` | 找到界面或后端实现；只表示功能存在，不等于完整验收通过。 |
| `[缺失]` | 在本地 2.0 的界面、路由及实现中未找到完整能力；不把旧 Discourse 自带功能算作新版已有。 |
| `[有问题]` | 功能已存在，但已复现故障，或源码明确不满足该功能要求。R 编号对应文末问题表。 |
| `[待核验]` | 有实现线索，但实际效果、权限或异常场景证据不足。 |
| `[待确认]` | 产品规则存在冲突，或属于建议增强，不能直接认定为必须开发。 |

同一功能可以有多个子状态，例如“任务查询接口已有，但归属校验有问题”。父节点仅用于分类；具体状态以子节点为准。所有“缺失”均限定于本次查看的本地 2.0 代码范围。

范围约定：画风、图型、作品、创作和社区是主线；ZIP 只记录为已有可选导出，不作为投稿或使用资源的前提。现金充值、收费经验帖等按条件列出，不擅自扩大需求。

## 需要先统一的产品规则

| 编号 | 现有分歧 | 文档处理方式 |
| --- | --- | --- |
| D01 | 旧产品文档要求不接现金支付、不扣社区积分，额度文档还存在每日 3 次与 5 张等差异；新版有积分扣费与现金充值按钮。 | 记录当前能力和缺陷，不把收费当作已获确认的最终需求。保留现金充值才需要支付订单、回调与对账；取消则应移除相关入口和接口。 |
| D02 | 仓库旧目标是扩展原 Discourse，新版实现了独立论坛和 SQLite 账号体系。 | 用户导入只能算部分承接；帖子、链接、附件、积分及解锁权益的迁移方案需要另定，不能默认已经迁完。 |
| D03 | 旧规则要求新经验来自公开论坛并保持免费，新版编辑器和钱包支持收费帖。 | 先确定哪些内容可收费，再定义作者发布、审核、解锁与退款流程。 |

这些差异标记为“待确认”，不会依据旧文档直接把新版已有功能判为错误，也不会把新版按钮当成已经确认的产品方向。

## 开发顺序建议

1. 先关闭权限绕过、匿名重置和无支付充值，修复缓存与历史记录归属。
2. 接通并明确真实生图状态，补任务去重、归属、恢复与私有图片保护。
3. 分离演示数据，校验真实作品与资源配图，修正新发和榜单规则。
4. 补齐账号找回、持久草稿、通知和用户内容编辑等日常使用缺口。
5. 精简手机入口，补新人指南和新版图片加载策略。
6. 完成新版部署、备份恢复、迁移与浏览器验收。
