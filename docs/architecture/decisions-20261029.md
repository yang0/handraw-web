# 架构决策记录 · 创始人已定（2026-10-29）

供架构师（Claude）与实现者（DeepSeek）共同遵循。以下三条由创始人明确拍板，**不再作为设计选项讨论**。

## D-01 作品主键

**决定：`works.id` 是作品主键。论坛帖只是作品的讨论区，不是第二条数据记录。**

含义：
- 广场、点赞、收藏、复刻、画风关联、skill 回执，全部以 `works.id` 为准。
- 作品与讨论帖的关系通过外键/映射表达，讨论帖不再承担"作品本体"职责。
- 同一作品在广场与论坛读到的是同一条记录、同一套计数、同一串评论。
- 一次分享多张图，原则上视为**一件作品**（多图放在 `images_json`）——除非架构师给出更强理由。

## D-02 审核边界

**决定：作品即时发布，审核只用于「进官方目录 / 精选」。**

含义：
- 用户发布作品 → 立即进入广场"最新"，可被浏览、可被复刻。
- 双人一致投票机制保留，但**仅用于作品进入官方目录、画风/图型进入官方目录或精选**。
- 作品发布不再等待审核，不再出现"论坛已发布、广场不存在"的不一致。
- 内容安全靠举报阈值 + 管理员巡查兜底，不靠发布前审核。

## D-03 skill 接口

**决定：改 skill 契约，在新后端实现新接口；不保留 `/studio/api/entries` 兼容层。**

**关键前提（创始人确认）：`E:\handraw-style` 的 skill 尚未对外发布，无存量用户。**

含义：
- 不需要兼容层，不需要双写，不需要考虑旧版用户断代。
- 新网站定义唯一的作品发布契约，`E:\handraw-style` 的 `community-share` skill 直接改调新接口。
- 仍须保证：分享成功后，skill 能拿到一个**可访问的作品链接**作为回执。
