# 全站交互方案（2026-10-30）

角色：设计与实现（Claude）。范围：首页、画风库、图型库、论坛列表、作品主帖、作品回执、共创投稿、创作台、文章编辑器、文章预览、管理后台。

视觉主题沿用现有规范，不新增设计语言：暖纸底 `--paper-bg #f6f3ec`、卡面 `--paper-card #fffdf9`、内衬 `--paper-inset #efeae0`、朱砂 `--vermilion #b74227`、衬线标题 `--font-serif`（`demo/assets/theme.css:2-33`）。本文所有新规则都只用这些变量。

## 0. 结论

| 问题 | 决定 |
|---|---|
| 不同比例的图放进卡片 | **固定 1:1 画框 + `contain` + 纸色衬底**。图完整显示，卡片等高，同行标题对齐 |
| 详情页主图 | **按图自身比例显示**，只限最大高度，不裁切 |
| 缩略图 | **同样是 1:1 画框 + `contain`**，不再用 `cover` 裁切 |
| 例外 | 头像、≤48px 的画风/图型识别小图可以 `cover`：它们是标识，不是作品本身 |
| 画风库、图型库 | 保留瀑布流（列高本来就不齐，不存在跨列标题对齐的问题） |
| 断点 | 手机 ≤720px，平板 721–1080px，桌面 ≥1081px |
| 新样式放哪里 | 新文件 `demo/assets/interaction.css`，四个入口页**最后**加载 |

## 1. 图片容器策略

把站内所有图片位分为三类容器和一个例外。判断依据只有一个：**这张图是不是用户要看的作品内容**。是作品内容，就一个像素都不能被裁掉。

### 1.1 卡片画框（Card Frame）

用在：首页「作品与做法」、首页「最新资源」、作品回执页的关联作品格子、论坛列表缩略图。

```css
aspect-ratio: 1 / 1;
object-fit: contain;
background: var(--paper-inset);   /* 衬纸 */
box-shadow: inset 0 0 0 1px var(--line-soft);   /* 画框内边线，让留白看起来是有意的 */
```

**为什么是 1:1**

- 当前 10 件种子作品里 9 件是 1024×1024，1 件是 768×1024。1:1 画框对 9 件完全没有留白。
- 创作台提供的比例主要是 1:1、3:4、4:3。1:1 正好处在 3:4 和 4:3 中间：竖图左右各留 12.5%，横图上下各留 12.5%，两边对称，任何一种都不会特别吃亏。
- 选 4:5 或 3:4 画框，会让占九成的方图上下都出现色带，得不偿失。

**为什么是 `contain` 而不是 `cover`**

- 手绘作品的标题字、落款、拼贴双图（例如 SC-021 双拼：上半实拍、下半手绘）经常贴着边。`cover` 会把「街头的黏土西装男」裁成只剩上半张实拍，看不到手绘那一半，等于把作品本身藏起来。
- 留白用衬纸色加 1px 内边线处理，看上去像装裱的卡纸，而不是加载失败。

**为什么不让卡片随图自然高（现状）**

- 现状就是这个方案：竖图卡 572px，方图卡 429px，同行标题错位，下一行整体下沉。首页是一个「精选橱窗」，用户横着扫标题，行对齐比多出的 25% 图面更重要。

**卡片文字区同时固定**：标题单行省略，作者单行，编号与「查看做法 →」同一行、两端对齐。图等高之后，文字区也等高，整行才真正对齐。

### 1.2 主图舞台（Stage）

用在：作品主帖大图、作品回执大图、资源详情大图、文章编辑器里已生成的配图卡。

```css
width: auto; max-width: 100%;
height: auto; max-height: min(72vh, 720px);
object-fit: contain;
```

- 舞台里只有一张图，没有对齐问题，所以**按图自身比例**显示。竖图就是竖的，横图就是横的。
- 只限最大高度，保证桌面上竖图不会撑出一屏半。舞台底色用衬纸色，竖图两侧的留白是舞台的一部分。
- 文章编辑器的配图卡原来把 4:3 的配图塞进 5.2:1 的横条（`max-height:216px` + `cover`），画面被裁掉三分之二。改为舞台规则，最大高度 360px。

### 1.3 缩略图（Thumb）

用在：主帖/回执的多图切换条、资源详情的缩略条、同组资源条、投稿页预览缩略图。

- 同样是 1:1 + `contain` + 衬纸底。
- 原因：缩略图是用来**选哪一张**的，裁掉一半就选不准。双拼图在 `cover` 缩略图里看起来和单图一样。

### 1.4 例外：识别标记

头像（`hw-user-avatar-circle-img`）、编辑器底栏的画风徽标（32px）、引用小芯片、论坛侧栏资源入口（≤48px）继续用 `cover`。它们只用来辨认「是哪一个」，不是让人看作品。

### 1.5 不在本次范围

创作台画布内部的节点缩略图（`ic-gen-img`、`ic-disp-*` 等）属于工作区工具界面，图本身在右侧和历史里可以完整查看，本次不改。

## 2. 栅格与间距

### 2.1 间距刻度

只用 8 个值，在 `interaction.css` 里定义为变量：

| 变量 | 值 | 用途 |
|---|---|---|
| `--sp-1` | 4px | 图标与文字之间 |
| `--sp-2` | 8px | 按钮组内间距、标签之间 |
| `--sp-3` | 12px | 卡片内文字块之间、列表项之间 |
| `--sp-4` | 16px | 卡片内边距（手机）、表单项之间 |
| `--sp-5` | 24px | 卡片栅格间距（桌面）、卡片内边距（桌面） |
| `--sp-6` | 32px | 页面左右边距（桌面） |
| `--sp-7` | 48px | 区块之间 |
| `--sp-8` | 64px | 页面顶部大留白 |

### 2.2 内容宽度

| 页面类型 | 最大宽度 |
|---|---|
| 浏览页（首页、库、论坛） | 1440px（沿用） |
| 详情页（作品回执、主帖正文） | 1040px，面包屑、正文、讨论、评论**同一列宽** |
| 写作页（文章编辑器纸面、配图卡） | 820px，纸面和配图卡同宽 |
| 表单页（共创投稿） | 760px |

### 2.3 卡片栅格

| 栅格 | 桌面 | 平板 | 手机 |
|---|---|---|---|
| 首页「作品与做法」 | 3 列，间距 24px | 3 列，间距 16px | 2 列，间距 12px |
| 首页「最新资源」 | 4 列 | 4 列 | 2 列 |
| 画风库/图型库瀑布流 | 沿用（用户可选 3/5/8 列） | 沿用 | 2 列，隐藏密度切换 |

手机改成 2 列的理由：现状 1 列时 6 张作品要滚 3000px，用户看不到「这里有很多作品」。2 列方框每张约 177px，足够看清画面。

## 3. 响应式断点

站内现有 20 个不同的断点值（720 用得最多，9 处）。新规则只用三个：

- **手机 ≤720px**：单列主内容；侧栏折叠为横向滚动的标签条；顶栏两行；所有可点目标 ≥40px。
- **平板 721–1080px**：论坛隐藏右侧栏（修复：右侧栏的内联 `display:flex` 盖过了样式表的隐藏规则）；编辑器历史列表变为顶部横条。
- **桌面 ≥1081px**：完整布局。

旧规则不批量改写，避免牵动面太大。

### 3.1 顶栏

- 桌面：「使用指南 / 消息」并入顶栏右侧，不再单独占一行（现在多出 25px 的空行）。
- 手机：第一行是品牌 + 搜索框 + 头像，第二行是频道导航（横向滚动）+ 指南/消息。顶栏从 172px 降到约 100px。
- 修复：手机样式写的是 `.hw-nav`，实际类名是 `.hw-nav-links`，横向滚动规则从未生效。
- 公告条在手机上最多两行。

## 4. 交互反馈

| 状态 | 规则 |
|---|---|
| 悬停 | 只在 `(hover: hover)` 设备上生效。卡片：边框转为朱砂浅色，阴影从 `--shadow-sm` 到 `--shadow-md`，标题转朱砂色。**去掉图片放大**：放大会把 `contain` 的图边缘推出画框，等于又裁了一次 |
| 按下 | 按钮 `transform: translateY(1px)`，80ms |
| 键盘焦点 | 全站统一 `outline: 2px solid var(--vermilion); outline-offset: 2px`，只在 `:focus-visible` |
| 加载 | 沿用 `img.hw-img-loading` 的纸色微光（`theme.css:765`）；画框底色就是衬纸色，图片没到时不会出现黑块或塌陷 |
| 空状态 | 虚线边框 + 居中灰字 + 一个朱砂色动作。创作台「还没有生成结果」改为这个样式 |
| 错误态 | 朱砂浅底 `--vermilion-wash` + 朱砂边，不用纯红 |
| 触控目标 | 手机上按钮、标签、链接最小 40px 高；主操作 44px |
| 动效 | `prefers-reduced-motion` 下全部去掉位移和过渡（`theme.css` 已有全局规则） |

## 6. 实现约束

- 新规则集中在 `demo/assets/interaction.css`，在 `index.html`、`forum.html`、`studio.html`、`admin.html` 中最后加载，靠加载顺序覆盖，尽量少用 `!important`。只有在需要盖过内联样式时才用。
- 业务逻辑只改一处：文章预览的进入与离开（§5）。
- 每次改 CSS/JS 都递增对应 `?v=N`。
- 新增测试 `tests/test_interaction_design.cjs`，只读已跟踪文件，检查：四个入口都最后加载 `interaction.css`；卡片画框是 1:1 + contain；作品画框里没有 `cover`；预览深链的待打开逻辑存在。
