# 论坛管理与私密论坛

超级管理员在后台「论坛 · 版主 · 悬赏 → 论坛管理」创建论坛，填写名称、介绍，选择公开或私密。关闭论坛会隐藏前台入口并拒绝普通访问和发帖，内容保留，重新开放即可恢复。

私密论坛按已注册账号邀请。管理员输入用户名，可一次邀请多位成员，也可撤销邀请。受邀账号登录后才能看到论坛链接；转发链接、猜测帖子 ID 或图片地址不能获得权限。超级管理员保留管理权限；运营员、审核员和版主也必须受邀才能访问私密内容。

新论坛可在论坛首页、发帖分类和版主配置中使用。作品讨论仍由作品评论发起，不作为普通发帖或移帖的目标。

## 权限与数据

- `forum_boards` 保存名称、介绍、公开/私密、开放/关闭、排序和并发版本。
- `forum_board_members` 保存邀请人、邀请时间和撤销时间；重复邀请不会生成重复成员。
- 论坛创建、设置变化、邀请和撤销都记录管理员审计。
- 列表、搜索、详情、回复、资源关联讨论、互动、编辑、个人主页、通知和媒体读取使用共同的论坛权限条件。公开统计不会包含私密讨论。
- 私密图片必须经过当前账号鉴权，响应为 `private, no-store`，每次读取重新检查授权；所有者对自己的原始上传仍保留访问权。
- 发布和互动事务锁定论坛行，关闭或撤销成员时等待已受理的事务结束。新请求在关闭或撤权后被拒绝。
- 前端详情缓存按账号及论坛权限范围隔离。退出登录、切换账号或刷新后权限变化，会清空旧帖子及回复，并丢弃旧请求的迟到响应。
- 已有私密帖子的论坛不能直接改成公开，也不能跨公开/私密范围移动帖子，避免意外公开历史内容。

公开资源或已公开的原始作品不会因为引用它的私密讨论而变成私有。曾经有权阅读的用户可能已保存内容；撤销邀请阻止后续访问，不能收回已经下载的副本。

## 接口

| 接口 | 用途 |
|---|---|
| `GET /api/forum/boards` | 当前账号可进入的论坛 |
| `GET /api/admin/forum-boards` | 管理员查看论坛与成员 |
| `POST /api/admin/forum-boards` | 创建论坛 |
| `POST /api/admin/forum-boards/{key}` | 更新名称、介绍、可见范围及开放状态；须提交 revision |
| `POST /api/admin/forum-boards/{key}/members` | 按 usernames 邀请；action=revoke 撤销 |

## 升级与回滚

备份后先应用新增迁移 `backend/postgres_122_forum_boards.sql`，再启用新代码。迁移可重复执行；自动登记现有合法分类，并保留原有帖子。新建测试数据库由 PostgreSQL bootstrap 自动应用。

代码启动会检查迁移 122。数据库不随代码回滚。创建私密论坛后，不可回滚到不支持论坛权限的旧代码，否则旧查询可能公开私密内容；修复时保留这层权限检查。

## 验收

隔离 PostgreSQL 覆盖邀请/撤销、并发重复邀请、关闭等待已受理事务、关闭/重开、并发版本、私密历史不可直接公开、直接帖子 URL 与匿名接口、互动与通知过滤、图片授权。真实 CDP 9221 覆盖后台创建、邀请、撤销、关闭和重开，游客/未受邀账号拒绝直接链接，受邀成员读取与回复，以及退出登录清空私密页面。代表宽度为 1440、820、390。最终测试、提交及部署状态见 #259。
